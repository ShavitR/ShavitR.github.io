Quickstart

Sell a digital file for USDC on your own hosted checkout:

git clone https://github.com/ShavitR/cryptopaywall && cd cryptopaywall
node bin/prepare.js product.zip --name "My Product" --price "$9 USDC"

prepare.js prints every environment variable - including a generated signing secret, a default three-chain config, and your file embedded as base64. Paste them into Vercel via the deploy button in the README. Total time: about five minutes.

No deployment at all? Use a Payment Link against any public CryptoPaywall instance.

Payment Links

A hosted checkout for any wallet, created by URL alone:

/api/link?to=0xYOUR_WALLET&amount=9&chain=base&name=My%20Product

Query parameters

ParamRequiredDescription
toyesWallet address receiving the payment (0x + 40 hex chars)
amountyesPrice in human units (e.g. 9 = $9 USDC)
chainnoComma list of enabled chains: ethereum, base, polygon. Default base
namenoProduct name shown to buyers (max 80 chars). Default "Payment"
redirectnoHTTPS success URL. Verified buyers are redirected there; __RECEIPT__ in the URL is replaced with the signed receipt token
tokennoERC-20 contract override (single-chain links only). Default: native USDC per chain
decimalsnoToken decimals override (single-chain only, 1-36). Default 6

The checkout page shows price, QR code, destination address, and a hash-verification form. It is marked noindex.

Try a real one now - this link runs on the live demo deployment:

Verify endpoint

POST /api/verify - check any transaction against any recipient. This powers Payment Links and can power your own integrations.

Request

{
  "txHash": "0x...",          // required, 66 hex chars
  "to":     "0xWALLET",       // required, expected payment destination
  "chains": [                 // optional, max 4
    { "id": "base", "name": "Base",
      "token": "0x8335...2913", "decimals": 6,
      "rpcs": ["https://mainnet.base.org"] }
  ],
  "minWei": "9000000",        // optional minimum in base units
  "decimals": 6               // fallback if chain omits decimals
}

Responses

StatusMeaning
200{ ok: true, amount, chain, token } - token is an HMAC-signed receipt (24h validity)
400Malformed input
402Transaction found but no qualifying transfer, or not yet confirmed
502All RPC endpoints unreachable - retry shortly

Receipt validation: the returned token is base64url(JSON) + . + HMAC-SHA256 signature over "subject:exp" using the server's secret. Validate it yourself, or accept it into your redirect URL and trust your own deployment's issuance.

Embed button

One script tag renders a "Pay with USDC" button anywhere - blog posts, docs, landing pages:

<script src="https://your-deployment.vercel.app/embed.js"
  data-to="0xYOUR_WALLET"
  data-amount="9"
  data-chain="base"
  data-name="My Product">
</script>

Attributes: data-to (required wallet), data-amount, data-chain (default base), data-name, data-label (button text). The button opens the Payment Link checkout in a new tab.

Webhooks (Pro Pack)

Replace api/unlock.js with api/webhook-unlock.js from the Pro Pack and set WEBHOOK_URL. Every verified payment POSTs:

{
  "event":  "payment.verified",
  "txHash": "0x...",
  "amount": 19,
  "chain":  "Base",
  "ts":     1787400000000
}

Header x-cryptopaywall-event: payment.verified. Timeout is 3 seconds; webhook failures never block buyer delivery.

Manual links (Pro Pack)

Mint a signed download link without payment - refunds, comps, press copies:

PAYWALL_SECRET=<your-secret> node bin/link.js \
  --url https://your-store.vercel.app --hours 48 --note "comp-jane"

Minted links use the same HMAC scheme as storefront links, so no server changes are required. Anyone holding your secret can mint unlimited links - treat it like a database password.
